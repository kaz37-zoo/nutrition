# 食事・服薬管理 — Nutrition Tracker

**Version 12 / nutrition audit final**  
**監査日: 2026-08-21**

毎日の食事、栄養、薬・サプリの服用を1つのPWAで管理するための個人向けWebアプリです。将来的にトレーニングAIと統合し、食事・栄養・服薬・トレーニング・回復を同じ日付データで扱える構造を目指しています。

> このアプリの栄養評価は健康管理の補助を目的としたものです。診断、治療、処方変更の判断には使用しないでください。

## 主な機能

### 食事管理

- 朝・間食 / 昼食 / 夕食の固定食材チェック
- 食材の追加・編集・削除
- 朝・昼・夕をまたぐ食材移動
- 同じ時間帯内での並べ替え
- 「どちらか1つでOK」の達成ルール
- 当日だけ量を変更 / デフォルト量を変更
- その他の食事の手動記録
- お気に入り・最近の記録からの再入力
- 週N回 / 月N回などの定期食材

### 栄養管理

- 厚生労働省「日本人の食事摂取基準（2025年版）」を基礎にした年齢・性別別評価
- カロリー、PFC、食物繊維、脂肪酸、ビタミン、ミネラルを広く記録
- n-3 / n-6、B6 / B12、葉酸、Mg、Cu、Mn、ヨウ素、Se、Cr、Moなどにも対応
- EPA+DHA、遊離糖などは日本のDRIとは分離して参考基準として表示
- DHA単独、EPA単独、β-カロテン、総糖類、糖質などを「公的な独立目標」と誤認しない設計
- 未測定・未確認を `0` とせず `unknown` として処理
- データ不足時は「不足」と断定せず判定保留
- 栄養素ごとの出典品質を保持

### 食品データ品質

食品ごと、さらに栄養素ごとに、以下のような品質区分を持ちます。

- `official` — 文科省FoodDB等で個別確認
- `mext-transform` — 文科省成分表を変換したデータから安全に補完
- `manufacturer` — メーカー公式表示
- `manufacturer-conflict` — 同一商品の公式情報同士に差異あり
- `proxy` — 類似する調理状態等による補完
- `estimated` / `derived` — 推定・計算値
- `legacy` — 旧アプリDB由来で一次再確認前
- `unknown` — 未測定・未確認

**`unknown` と `0` は別物です。**

### 生・ゆで・冷凍野菜

代表的な野菜は調理状態を分離しています。

- ほうれん草：生 / ゆで / 冷凍・ゆで
- 小松菜：生 / ゆで / 冷凍・標準
- ブロッコリー：生 / ゆで / 冷凍・標準
- 枝豆：生 / ゆで / 冷凍
- 人参：生 / ゆで

文科省に冷凍食品そのものの収載値がある場合はそれを優先し、存在しない場合はメーカー表示の代表値と文科省の近似調理状態を分けて保持します。

### MEXT安全補完

食材マスタの **「MEXT不足データを安全に補完」** から、一意に対応できる食品だけ不足栄養素を補完できます。

- 自動補完候補: 165食品
- 厳格な名称トークンルール: 161食品
- 残りは検証済み野菜エイリアスで対応
- 曖昧な食品、商品依存食品、複合料理、サプリは強制マッピングしません

補完元は文科省成分表をJSON化した公開変換データです。**文科省FoodDBを1食品ずつ一次確認したデータとは区別して表示します。**

また、変換データでは元表の `(0)` と括弧付き推計値が同じ表現に正規化される箇所があるため、その値は安全側に `unknown` とし、0とは断定しません。

### 薬・サプリ管理

- 薬 / サプリを分離して登録
- 毎日 / 曜日指定 / 週N回 / 月N回
- 服用時刻
- 「飲んだ / 後で / スキップ」
- 服用実績時刻を保存
- 30分スヌーズ
- 未服用警告
- サプリは服用済みの時だけ栄養計算へ反映
- 薬は栄養計算へ含めない

DHCビタミンBミックス、DHCビタミンCはメーカー公式の現在表示を反映しています。

ULBO Platinumは公式サイトと公式ショップで亜鉛量の表記に差異が確認されたため、汎用項目では亜鉛を未確定とし、12mg版 / 14mg版を別項目として用意しています。

### 記録・履歴

- 食事達成率
- 薬・サプリ服用率
- 総合達成率
- カレンダー
- 栄養素推移グラフ
- 期間平均
- ウエスト記録

旧バージョンで保存していなかった新しい栄養素を、過去日に `0` と補完しません。データが存在しない日は欠損として扱います。

### AI連携

- 不足栄養素の相談プロンプト
- 食事評価プロンプト
- 週間レビュー
- 料理の栄養情報をJSONで取り込み

AI入力では次を要求します。

- 不明値は `null`
- 推定値は `_est`
- `carb` は総炭水化物
- `freeSugar` と総糖類を混同しない
- ナイアシンは可能ならmgNE
- EPA / DHAは別々に返す
- プリン体は信頼できる出典がなければ `null`

## iPhone向けUI

Version 12ではiPhoneでの片手操作を優先して調整しています。

- 主要操作の最小タップ領域 44px
- 全チェックを対象リストの近くへ配置
- 大型チェック・編集・移動ボタン
- safe-area対応
- 入力欄16px以上でSafariの意図しないズームを抑制
- 狭い画面では薬・サプリ操作を再配置

自動回帰テストでは **320 / 375 / 390 / 430px** の4幅で、表示中の主要操作に44px未満のタップ領域がないことを確認しています。

## データ保存

データは端末の `localStorage` に保存されます。

Version 12でも既存v11の保存キーを維持し、既存ユーザーデータを壊さないようにしています。内部 `schemaVersion` は12です。

バックアップ機能では以下をJSONに保存できます。

- 食事設定
- 日別記録
- 薬・サプリ設定・実績
- 履歴
- ウエスト
- お気に入り
- カスタム食材
- MEXT補完キャッシュ

## 通知について

アプリ起動中は指定時刻、未服用、スヌーズの管理が可能です。

`sw.js` はWeb Push通知を受信できますが、**iPhoneでPWAを閉じている間にも指定時刻に確実に通知するには、Web Push送信側のサーバーが別途必要です。** 静的GitHub Pagesだけではサーバー側の予約送信までは行いません。

## 既知の限界

- 内蔵217食品のうち、旧DB由来の値はまだ多数残っています。
- MEXT補完は一意に対応できる食品だけを対象とし、曖昧な名称は補完しません。
- EPA/DHA個別値、遊離糖、プリン体などは文科省本表だけでは全食品を埋められません。
- データ充足率は現在「記録項目数ベース」であり、重量寄与率ではありません。
- 加工食品・市販商品は製品改訂で栄養表示が変わる可能性があります。
- 冷凍野菜は商品差があるため、文科省に冷凍値がない食品は代表値/Proxyです。
- バックグラウンドの確実な服薬通知にはWeb Push送信サーバーが必要です。

## 次の統合段階

トレーニングAIとの統合では、同一日付キーに次を集約できる状態です。

- 食事・栄養
- 薬・サプリ服用
- 睡眠
- 疲労度
- 筋肉痛
- トレーニング内容
- RIR
- 体重・ウエスト

栄養値にはデータ品質情報を保持しているため、AI側でも「本当に不足している」と「食品データが不足している」を区別できます。
